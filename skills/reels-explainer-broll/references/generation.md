# Model and generation policy

## Match the engine to the task

| Task | Preferred route | Why |
|---|---|---|
| Counter, exact time axis, text labels, branded numeric comparison | Deterministic native motion graphics; actual brand font; separate asset | Exact values, repeatable timing and no generative typography drift |
| Simple cinematic insert with little semantic change | Economical video model meeting resolution and motion requirements | Avoid premium spend without visual benefit |
| Complex human-to-anatomy transition, ordered transformations, stable identity | Strong current reference-capable cinematic video model | Quality and reference adherence matter more than lowest price |
| Geometry or placement correction in storyboard | Targeted image edit | Fix the source before paying for video |
| Small timing/export/compositing correction | Deterministic media editing, preserving accepted footage | Avoid regenerating correct content |

Do not hardcode a permanent “best model” or price. Inspect current connected model capabilities and cost tools when needed. Provider catalogs are preferred to web guesses. Choose based on supported image/video roles, duration, output quality, identity, temporal control and available account plan. A premium subscription does not imply every feature is free. A higher resolution does not prove better anatomy or temporal reasoning.

Historical project evidence: Seedance 2.5 at 1080p with high bitrate produced accepted complex cutaways after ordered state images were supplied. It still failed exact counting and sometimes ignored side/state constraints. Treat this as local evidence, not a universal ranking. The assistant model’s tokens and media provider credits are separate budgets.

## Prompt contract

Use a compact, structured brief, removing contradictions and redundant instructions:

1. Deliverable: ONE continuous clip, duration, ratio, audio/text policy.
2. Reference map: explicit numbered image roles in story order; video role limited to approved style/identity/transition qualities.
3. Full arc: opening, central actions, ending. Carry forward accepted details even if the latest user message concerns only one correction.
4. Timed actions: feasible windows linked to actual speech; readable hold for the central takeaway.
5. State invariants: identity, camera orientation, side mapping, geometry, active markers. Explicitly state the unchanged side during a one-sided transformation.
6. Render requirements: natural skin/material detail, realistic light, coherent volume, stable topology, physical camera movement. No flat slideshow when cinematic motion is requested.
7. Narrow exclusions drawn from real failure risks.
8. Endpoint: what the final frame must show and how long it holds.

Do not overconstrain a five-second shot with a dozen simultaneous events. Split complex information into separate explanatory assets when approved, rather than making the video model solve exact counters and medical morphs simultaneously.

## Reference and cost preflight

Confirm asset accessibility, ordered IDs and correct account/project. Generated files must be saved durably; remote sandbox paths can expire. Use provider-supported upload methods and await confirmation; never relay image bytes as massive prompt/base64 chunks. Reuse successful uploads, refresh expired upload URLs, and never confuse an uploaded reference with a completed video.

Estimate the actual request with duration, resolution, reference modes, count and extras. Report total per scene/batch, not only a per-second rate. Respect the user's explicit economy/quality priorities. Do not use a top video model for a deterministic counter by default.

One scene approval authorizes its agreed output, not arbitrary variants. At scale, propose an approved scene list and budget; first generate a representative complex pilot, then reuse the accepted visual rules. Batch only independent approved scenes and preserve their ordered identifiers. Do not multiply attempts just because concurrency is available.

## Separate overlays

Generate/edit exact overlays separately, using actual fonts and colors read from the brand reference. Prefer alpha export when supported and verified; otherwise provide black-background graphics with Screen instructions. Never call black background transparency. Supply position, duration, source insertion time and overlay blend mode.

Check EVERY counter value, including single-frame boundaries and ending. Native tools can also overlap text at boundaries, so inspect the exported pixels, not only the code. If the user explicitly requests a generative counter, allow the authorized attempt; reject wrong values and explain a deterministic correction instead of claiming the prompt solved it.

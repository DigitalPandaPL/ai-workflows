# Acceptance and repair

## Check against intent, not merely attractiveness

Confirm actual duration, orientation, resolution and audio. Inspect context, each state, each transition and ending; use dense samples/full playback near rapid changes. Sampling every half second can find gross sequence errors but cannot certify every frame. State the verification limits.

Evaluate separately:
- Meaning: does the visual actually express the spoken idea? Could the same image reasonably communicate the opposite?
- Order: all required states appear in order, no reversed correction, no missing opening or ending.
- Continuity: one subject, stable sides, plausible scale, no duplicate/missing parts, no unexplained clothing/skin changes.
- Effects: correct locations, intended intensity differences, exact on/off transitions; no unintended quantified claims.
- Motion: real continuous change, not merely a still with zoom; no jarring transition or unreadably rapid event.
- Timing: compare actual action times with actual speech, not just requested timestamps.
- Brand: colors, typography when present, style, contrast and caption-safe area.
- Overlays: every exact value and character, stable glyphs, no unintended ruler marks, no overlapping digits.

Critical failures (wrong anatomy, reversed sequence, wrong identity/side, misleading meaning, broken counter, missing required scene) are not “final.” Minor timing offsets can be suitable for retiming if the user’s requested deliverable allows it; report the needed adjustment. A generated job status alone never implies acceptance.

## Repair decision

Locate the cause before choosing a remedy:
1. Concept ambiguous → fix the explanation/storyboard.
2. Image incorrect → targeted image edit, preserve unrelated approved content.
3. Ordered refs treated as alternatives → clarify state roles and simplify transitions; do not guarantee compliance.
4. Correct story but timing offset → retime locally when feasible, preserving motion quality.
5. Exact typography/count failure → separate controlled overlay.
6. Only a local visual defect → evaluate targeted video edit; otherwise prepare a scoped re-generation brief.

Keep source output and QA notes for traceability, clearly distinguish rejected outputs from deliverables. Do not quietly substitute four films for one, a slideshow for cinematic footage, or a software mockup for a realistic render. Do not launch additional paid iterations beyond agreed authorization. For repeated failure of the same constraint, change strategy before requesting another spend.

## Scale without losing control

Use acceptance conditions per scene and per shared visual style. Reuse approved subject/setting references and prompts with explicit deltas. Representative-pilot acceptance can cover style, not automatically every subsequent semantic change. Track cumulative actual spend when available and pending/unknown submissions to prevent duplicates. Do not claim this workflow eliminates all future errors; measure usable-output rate and categorize actual failures to refine the skill narrowly.
